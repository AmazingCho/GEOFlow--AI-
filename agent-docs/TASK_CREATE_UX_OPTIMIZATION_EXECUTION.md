# 创建任务页 UX 优化执行说明

## 产品目标

在不改变任务、RAG、Entity、Case、图片和分发数据结构的前提下，降低创建任务时的认知负担，并避免新任务在用户未明确确认时进入自动发布链路。

## 本轮范围

1. 新建任务默认进入审核，发布范围默认仅本站。
2. 保留正文提示词和 AI 模型为核心配置，将 Skill、Style 和模型故障切换收入“高级生成设置”。
3. Collection 选择后，向用户显示当前可选 Entity 与 Case 数量，并解释无结果状态。
4. 桌面端与移动端操作区都回归正常文档流，彻底避免悬浮层遮挡输入区域。
5. 在提交区域同步展示必填完成度与发布风险状态。

## 兼容边界

- 不删除或改名现有表单字段。
- 编辑已有任务时继续显示并保存原有 `need_review`、`publish_scope`、Skill、Style 和模型策略。
- 用户仍可主动关闭审核、选择分发范围或开启跨 Collection。
- 后端继续校验 Entity、Case、知识库、图库与 Collection 的一致性。
- 不调整队列、文章生成、RAG 检索和分发服务实现。

## 验收标准

- 新建页默认勾选审核，默认选中“仅本站”。
- 直接提交且未传发布设置时，后端仍保存为安全默认值。
- 高级生成设置在新建页默认折叠，编辑已有高级配置时自动展开。
- 切换 Collection 或跨 Collection 后，可选 Entity/Case 数量即时更新。
- 桌面和移动端均不存在底部操作栏遮挡最后一个输入区域的问题。
- `AdminTasksPageTest`、PHP lint 和浏览器截图检查通过。
