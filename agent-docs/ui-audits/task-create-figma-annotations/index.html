Step 2 · 内容策略与知识来源

一般

1

P1：Master Prompt、Skill、Style 与模型同时出现，概念负担较大。默认只展示系统推荐结果，允许展开后人工覆盖。

Step 3 · 审核与内容分发

有风险
1 2
1

P0：审核与发布属于高风险动作，不宜与普通生成配置采用相同默认强度。建议默认“生成草稿，不自动发布”。

2

P1：渠道、审核规则和发布状态应按“生成 → 审核 → 分发”顺序组织，并明确哪些设置会立即产生外部动作。

Step 4 · Collection 与 Entity 联动

良好
1 2
1

保留：选择 Collection 后过滤 Entity 的方向正确，是任务上下文收敛的重要入口。建议补充结果数量和“为何不可选”的空状态。

2

P1：联动说明文案仍偏系统术语，应改为用户结果语言，例如“仅显示此业务容器中的实体”。

Step 5 · 移动端与窄屏

较差
1 2
1

P1：移动端单页过长，用户缺少当前进度感。建议采用分步导航或可折叠章节，并显示“必填项完成度”。

2

P0：底部固定栏在窄屏占据过多高度，遮挡输入控件。应缩为单行主按钮，并将次要动作放入菜单。

优先级路线图

P0 · 立即修复

  • 消除底部固定栏遮挡
  • 默认生成草稿，不自动发布
  • 明确必填项与未完成状态
  • 移动端压缩操作栏高度

P1 · 流程重组

  • 按“上下文、生成、审核、分发”分组
  • 默认隐藏 Master Prompt、Skill、Style 等高级项
  • 让系统推荐成为默认，人工选择作为覆盖
  • 移动端使用分步或折叠结构

P2 · 体验打磨

  • 补充 Collection / Entity 结果数量
  • 优化业务化说明和空状态
  • 增加任务配置摘要与风险提示
  • 统一输入框、下拉框和章节标题层级
